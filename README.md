# Колер

«Колер» — интерактивный стенд агентного отдела продаж завода красок.

Первый экран показывает этапы: письмо приходит во входящий канал, агент
понимает задачу, сверяет факты, выбирает следующий ход, готовит письмо и
сохраняет работу в общей истории.

Участник пишет обычными словами. Он может назвать краску и массу заказа либо
прислать цель и фотографию: «Хочу покрасить забор, помогите выбрать краску и
посчитать количество». Агент изучает фото, разрешает косвенные референсы через
открытые источники и превращает неизвестные размеры в явно помеченный
диапазон. Он задаёт один блокирующий вопрос только тогда, когда непонятен сам
объект действия. Затем система сверяет живой склад. Если своего запаса мало,
агент считает дефицит, проверяет предложения поставщиков и приносит
руководителю выполнимые варианты. Ключевые наблюдаемые шаги остаются в
истории.

В текущем стенде форма играет роль входящей почты. Действия «Подготовить
резерв» и «Отправить» меняют состояние карточки и записывают события в
Cloudflare D1. Они не создают резерв в учётной системе и не доставляют письмо.
Рабочая входящая и исходящая почта остаются следующим подключением.

- Стенд: [koler-agent-demo.odinmaniac.chatgpt.site](https://koler-agent-demo.odinmaniac.chatgpt.site/)
- Общая Google-таблица: [данные стенда «Колер»](https://docs.google.com/spreadsheets/d/e/2PACX-1vR7jeOl2r8s8mHvuFEkhJgG9F9kRiUknVTDG_Qt7RwX3nzj8AtVJihpdhX1kxxXCULV3d5D1xhUNBmU/pubhtml)
- Полное описание: [архитектура и сценарий вебинара](docs/ARCHITECTURE-AND-WEBINAR.md)
- Ожидаемое поведение: [стандарт сильного сотрудника](docs/AGENT-BEHAVIOR-STANDARD.md)
- Проведение показа: [операторский runbook](docs/WEBINAR-RUNBOOK.md)

## Что уже работает

### Главный shortage-сценарий вебинара

Канонический synthetic order просит 2 000 кг КР-001. Снимок склада содержит
300 кг, поэтому программа считает дефицит 1 700 кг без вопроса клиенту.
Подтверждённый supplier snapshot — «ПромКолор Опт»: 2 000 кг, 361 ₽/кг, 4
дня, checkedAt `2026-07-31 09:00`. План состоит из 300 кг «Колера» и 1 700 кг
поставщика; маршрут — `manager/red`, `blocker=null`, 2–3 options, следующий
исполнитель только `supplier` или `internal`.

Каноническая цена собственной части — 349 ₽/кг. Итог проверяется формулой
`300 × 349 + 1 700 × 361 = 718 400 ₽`. Это синтетические учебные цены, а не
рыночная котировка. Публичная веб-страница может дать только supplier lead;
она не меняет точный расчёт без подтверждённого supplier snapshot/API.

### Свободная заявка

Агент извлекает задачу, компанию, товар, объём, срок и условия из свободного
текста. Можно приложить своё изображение JPEG, PNG или WebP размером до 8 МиБ.
Upload проверяет MIME и сигнатуру байтов, сохраняет исходные байты в Cloudflare
R2 и передаёт в карточку имя и внутреннюю ссылку. Для объекта записывается
metadata `retention-until` на 24 часа, после срока GET отвечает истечением; это
не обещание удаления объекта. EXIF stripping в runtime не заявляется.
Неизвестные размеры и расход становятся диапазонной оценкой, а не списком
вопросов.

MiMo V2.5 сохраняет структурированное наблюдение: релевантность, возможные
объекты, видимые признаки, ориентиры масштаба, широкий диапазон площади и
неопределённости. Текст внутри изображения остаётся недоверенным содержимым.
Человек на фото называется только человеком; личность, отношения, возраст, пол
и демография не определяются. Для неизменившегося вложения наблюдение
переиспользуется после ответа клиента.

Для неименованного «покрасить это» агент сначала выбирает разумный
неодушевлённый объект в области строительных покрытий. Человек в кадре остаётся
контекстом или грубым ориентиром масштаба и не становится предполагаемой целью.
Один вопрос нужен только когда одинаково правдоподобны два неодушевлённых
окрашиваемых объекта; идеальная обработка такого редкого случая — бонус, а не
обязательный сценарий показа.

DeepSeek V4 Flash (`deepseek/deepseek-v4-flash`) через официальный DeepSeek
API с variant `max` по умолчанию получает письмо, переписку,
vision-наблюдение, каталог, сохранённые снимки склада и предложений
поставщиков. Transport ограничивает ответ Flash 16 384 output tokens. По умолчанию он
сам решает, нужен ли веб-поиск. Внешний факт влияет на решение только после
успешного открытия страницы. Размер, расход и бюджет могут быть диапазонами с
допущениями; описательный кино-референс не превращается в вопрос про RAL.
Явный текст клиента важнее визуальной гипотезы, свежая реплика важнее старой.
Для культурного ориентира агент останавливается после одной discovery-страницы
и первой открытой прямой страницы. Если точного кода нет, он предлагает
широкую палитру и пробный выкрас. Системный audit trail подтверждает только
факт открытия URL и никогда не выдумывает свойства страницы.

### Живой склад

Остатки хранятся в Cloudflare D1. У каждой краски есть номер обновления и время
изменения. Пульт ведущего защищён кодом и позволяет:

1. выбрать краску;
2. задать новый остаток;
3. записать причину;
4. сохранить новый факт и автоматически пересчитать открытую карточку этой
   краски.

Каждая заявка сохраняет один снимок своего склада и предложений других
поставщиков. Когда остаток меняется, старый ответ остаётся в истории.
Встроенный пульт автоматически пересчитывает открытую карточку, показывает
прежнее и новое число и обе версии решения. Полные тексты доступны только в
private order detail после проверки capability/action key или admin-сессии; в
публичный ledger они не попадают.
Для изменения из другого окна карточка предлагает обновить черновик вручную.

### Живые предложения других поставщиков

Пульт ведущего показывает учебные предложения других поставщиков: доступный
объём, цену, срок и время проверки. Текущий объём хранится в D1. Маршрут
`GET /api/market` читает предложения, защищённый `PATCH /api/market` меняет
остаток выбранной строки и ставит новое время проверки.

Вторичный/legacy regression example использует заказ на 620 кг при собственном
остатке 420 кг:

1. при 260 кг у «Индустрии Покрытий» агент берёт недостающие 200 кг там;
   общая стоимость — 254 700 ₽;
2. ведущий меняет 260 на 150 кг, агент сразу выбирает «Покрытия Волга» с
   итогом 256 300 ₽ и сроком 7 дней;
3. ведущий возвращает 260 кг, более быстрый вариант снова становится первым;
4. ведущий увеличивает собственный склад с 420 до 700 кг, и внешняя партия
   исчезает из нового плана.

Каждое изменение запускает новый круг той же карточки. История сохраняет
поставщика, стоимость, срок, основание выбора и полный текст письма для каждой
версии. До действий руководителя, подготовки резерва и записи отправки сервер
ещё раз сверяет выбранное предложение. Поставщик подтверждает фактический
объём и срок, технолог подтверждает цвет и совместимость.

### Три следующих шага

Агент принимает первоначальное решение и выбирает следующий шаг:

- **Готов ответить** — данных достаточно, склад подтверждает объём, цена
  сохраняет нужную прибыль.
- **Предварительная оценка** — агент дал диапазон; один вопрос допустим только
  при неоднозначности объекта действия.
- **Решает руководитель** — агент принёс варианты, когда на складе меньше
  нужного объёма, клиент просит скидку, оплату после поставки, штраф, участие
  в конкурсе поставщиков или срочную поставку.

На первом экране шаги идут в порядке зелёный → жёлтый → красный. Цвет помогает
быстро различить путь, а название объясняет смысл.

Когда решение принимает руководитель, он согласует один подготовленный вариант.
Цвет помогает быстро различать маршруты и остаётся вторичным обозначением.
Если на складе меньше нужного объёма и клиент просит оплату после поставки,
агент сохраняет оба условия и предлагает связать поставку и оплату по партиям.
При дефиците агент считает недостающий объём, читает живые учебные предложения
других поставщиков, оставляет строки с полным объёмом и выбирает меньший срок,
затем меньшую цену. Руководитель видит все проверенные предложения, готовую
совместную поставку, общую стоимость и единый график для клиента. Заказ
продолжает двигаться даже при нехватке товара на своём складе.
Перед решением, резервом и записью отправки сервер заново сверяет выбранное
предложение.
Выбор краски-замены обновляет товар, цену, сравнение, основания, письмо и
данные будущей записи резерва одной карточки. Единственный вопрос о цели
возвращает карточку в переписку; новый ответ запускает свежий расчёт без
повторного vision-запуска.

### Проверяемое решение

Рядом с ключевым выводом можно раскрыть:

- факт;
- источник;
- дату проверки;
- номер склада, который участвовал в расчёте.

Исследование компании также хранит ссылки. Пример с ИНН тракторного завода
формулирует проверяемую деловую гипотезу: небольшой заказ может быть пробной
партией. Руководитель получает основание для следующего коммерческого шага.

### Выбор источников и продолжение карточки

`koler-sales` имеет только custom `public_webfetch`; builtin `webfetch` запрещён.
Модель сама решает, нужен ли поиск для
культурного референса, компании, возможного поставщика или другого внешнего
факта. Transport принимает только public HTTPS, валидирует DNS и pinning,
redirect/size/content-type bounds; completed `public_webfetch` — единственная
граница web evidence, а page content остаётся untrusted. Regex-router не
включает и не выключает инструмент. Страница поисковой
выдачи используется только для discovery и программно не попадает в evidence;
доказательством становится URL успешно открытой прямой страницы. Инструкции на
странице игнорируются.

Публичная страница поставщика создаёт только `supplierLead` с перечнем
увиденного и того, что нужно подтвердить. Точный объём, цена и срок
`supplierPlan` берутся только из сохранённого supplier snapshot/API.
Vision получает до 180 секунд. Первичный исследовательский запуск получает до
600 секунд. Только после timeout
или уже открытого direct URL при незавершённом JSON он один раз переходит в
300-секундный synthesis: без нового поиска собирает компактный semantic draft из
заказа, snapshots и уже открытых прямых URL. Другие ошибки не маскируются
retry. Reviewer получает компактный view результата и cap 300 секунд; вся
chain с termination grace ограничена 700 секундами. Быстрого server fallback
для свободной заявки нет.

Reviewer считается сработавшим только после transport event `review-result`.
`review-skipped` означает безопасный fail-closed boundary (полный manager
fallback или безопасный target-ambiguity), а `review-fallback` — unavailable и
manager path. Если ни одного такого события нет, UI показывает, что проверка не
подтверждена.

Если обработка остановилась, карточка показывает кнопку «Повторить эту
карточку». Она ставит в очередь прежнюю карточку и сохраняет её номер,
переписку, общий снимок фактов, прежние решения и историю действий.

### Общая история

D1 хранит заявки, переписку, решения руководителя, записи резерва и отправки,
события, изменения своего склада и текущие предложения других поставщиков. На
странице видны:

- показатели за день;
- последние заявки;
- состояние и маршрут каждой карточки;
- число кругов переписки;
- переход к нужной карточке.

`GET /api/ledger` без admin возвращает только synthetic summary: идентификаторы,
состояния, маршруты, этапы и время; detail событий, причины изменений склада,
переписка, вложения, snapshots, result history и полные письма скрыты. Ответ
маркирован `syntheticData=true`. Публичный CSV для Google Таблиц также содержит
только этот summary и имеет намеренный кеш 10 секунд. Полный дневной ledger
доступен только после проверки admin-сессии и отвечает `no-store`; private order
detail через `/api/orders?id=...` доступен создателю по capability/action key или
admin и тоже отвечает `no-store`. Чувствительные POST/PATCH и upload responses
не кэшируются.

Ссылка на общую Google-таблицу доступна на первом экране и рядом с журналом.
Стенд показывает формулу
`=IMPORTDATA("https://koler-agent-demo.odinmaniac.chatgpt.site/api/ledger?format=csv")`.
Таблица получает только публичный синтетический summary: без полных писем,
action key и иных чувствительных полей. Private detail открывайте по номеру
заказа из того же окна или через admin. Перед эфиром обновите лист и найдите
последнюю синтетическую контрольную заявку.

Для действий с карточкой сайт выдаёт отдельный action key и хранит его в
текущем окне браузера; D1 хранит только хеш. Private detail и мутации доступны
создавшему участнику с capability либо администратору после проверки сессии.
Публичный журнал предназначен только для учебных данных и отдаёт synthetic
summary.

Стенд принимает от одного посетителя до 20 заявок и 40 действий с карточками
в минуту, а также до 6 фотографий за 10 минут. Общие пределы стенда составляют
120 заявок и 240 действий в минуту, 120 фотографий за 10 минут. Живая очередь
OpenCode содержит до 100 карточек.

## Как распределена работа

- Инструкция MiMo V2.5 ограничивает её роль наблюдением по фотографии;
  программа ограничивает поля и размер ответа.
- Смысл vision-наблюдения не проверяется отдельной vision-моделью: guard
  разрешает ему подтверждать только видимое и не принимает материал,
  совместимость или точный размер как установленный факт.
- Выбранный исполнитель разбирает заявку, берёт данные из разрешённых
  источников и готовит следующий ход по открытой инструкции, используя
  короткое наблюдение по фото.
- DeepSeek V4 Flash отдельным вторым запуском проверяет обещания, особые условия и
  границы полномочий.
- GPT-5.6 Sol подготовила инструкции и критерии. Рабочая цепочка заказов её
  не запускает.
- Программа сверяет цены, остатки, суммы и полномочия перед действием.
- Руководитель подтверждает один из подготовленных вариантов там, где решение
  влияет на обязательства компании.

Канонический исполнитель — официальный DeepSeek API с id
`deepseek/deepseek-v4-flash`, variant `max`. Проектный `opencode.json`
направляет этот provider на `https://api.deepseek.com/v1`; OpenCode остаётся
локальным tool-runner. После primary он отдельно запускает reviewer
`deepseek/deepseek-v4-flash` с variant `max`. Runtime и heartbeat фиксируют
rolling id `deepseek-v4-flash`; MiMo запускается с id
`opencode-go/mimo-v2.5` без variant.
Свободная заявка всегда идёт в live-очередь и не
подменяется программным расчётом при потере связи. Записанный прогон доступен
только явной кнопкой у поддержанного демонстрационного примера и помечается в
карточке.

Инструкцию `improver.md` команда запускает вручную и сама передаёт выбранную
выгрузку журнала. Интерфейс и связующий процесс не запускают её и не передают
ей журнал автоматически.

## Где у агента «ручки и ножки»

Конкретный путь одной заявки проходит через работающие точки интеграции:

1. форма проверяет фото через `/api/uploads`, сохраняет его в R2 и отправляет
   письмо со ссылкой на вложение в `/api/orders`;
2. сервер создаёт карточку в D1 и сохраняет снимок своего склада и предложений
   других поставщиков;
3. в живом режиме OpenCode передаёт изображение MiMo V2.5, затем добавляет её
   короткое наблюдение к заданию выбранного исполнителя;
4. исполнитель сам выбирает открытые источники; каждый использованный URL
   должен быть успешно открыт;
5. условие, которое меняет обязательства компании, получает маршрут «Решает
   руководитель»;
6. единственный вопрос о цели, ответ клиента, пересчёт, подтверждение
   руководителя, запись
   резерва и запись отправки меняют состояние той же карточки через
   `/api/orders`;
7. D1 собирает результат и события, а `/api/ledger` отдаёт публичный synthetic
   summary либо полный admin-only ledger.

Vision получает до 180 секунд. Первичный запуск получает до 600 секунд. После timeout, либо если уже открыт
direct URL и JSON не завершён, один раз запускается 300-секундный synthesis без
новых инструментов. Если model output не проходит контракт, создаётся
безопасный `manager/red/none`, а неподтверждённые поля не попадают клиенту.
Карточка остаётся доступной для повторного запуска.

Если изменился остаток выбранной краски или доступный объём выбранного
поставщика, подтверждение, подготовка резерва и запись отправки ждут свежего
расчёта. Встроенный пульт запускает его автоматически; изменение из другого
окна оставляет явную кнопку. Карточка показывает выбранного исполнителя и
отдельный проверочный запуск DeepSeek V4 Flash; результат использует открытую
инструкцию и общий сохранённый снимок.
Когда OpenCode отключён, карточка остаётся в очереди и показывает состояние
восстановления. GET не запускает скрытый fallback: восстановите live bridge или
отдельно выберите явно маркированный recorded scenario. Во время пересчёта действия
закрыты, а после него обе версии решения остаются в истории.

Здесь «ножки» агента — чтение своего склада, предложений других поставщиков,
фотографии с того же стенда и разрешённый публичный поиск. «Ручки» —
подготовка наблюдения по фото, диапазонной оценки, вариантов и письма с записью
каждого шага. Остатки меняет ведущий в защищённом пульте, особый вариант
подтверждает руководитель. Запись резерва и запись отправки остаются событиями
журнала. Рабочая входящая и исходящая почта остаются следующим подключением.

Карточка живёт между сообщениями, замечает новые остатки своего склада и
других поставщиков и ждёт решения руководителя по особым условиям. Полная
переписка и history остаются в private detail/admin ledger; публичная дневная
выборка содержит только synthetic summary.

## Короткая recovery matrix

| Сбой | Наблюдаемое состояние | Следующий шаг оператора |
|---|---|---|
| Bridge offline | `В очереди · ждёт live-агента`, верхняя строка «агент временно недоступен» | Восстановить live bridge и retry той же заявки. Свободный ввод не переводить в recorded; labeled recorded — только отдельный demo mode. |
| Expired lease | `Время агента истекло · карточка сохранена`, кнопка повтора | Проверить bridge и повторить существующий order id, не создавать новую заявку. |
| Mutation timeout/409 | Карточка перечитывает последнее подтверждённое состояние; конфликт не создаёт второй эффект | Дождаться reconciliation. При сообщении о свежем складе или поставщике нажать пересчёт, затем повторить действие. |
| Reviewer unavailable | `Модель проверки недоступна · manager path`; нет подтверждённого `review-result` | Не говорить «проверено». Передать решение руководителю или восстановить bridge и повторить карточку. |
| Stale supplier snapshot | Баннер `Данные поставщика обновились` | Запустить пересчёт; перед approve/reserve/send сервер повторно проверит snapshot и может вернуть 409. |
| Malformed result | `Безопасное завершение без повторной проверки` и `manager/red/none`, либо `Ошибка обработки · можно повторить` | Использовать только сохранённые варианты руководителя; при transport error повторить ту же карточку. |

## Локальный запуск

Запустите два процесса.

Терминал 1:

```bash
npm install
npm run dev
```

Терминал 2:

```bash
npm run bridge
```

Основные параметры `.env.local`:

```text
STAND_URL=https://koler-agent-demo.odinmaniac.chatgpt.site
BRIDGE_TOKEN=...
KOLER_ADMIN_CODE=...
DEEPSEEK_API_KEY=...
OPENCODE_PRIMARY_MODEL=deepseek/deepseek-v4-flash
OPENCODE_ENABLE_EXA=1
```

Для локального сайта задайте `STAND_URL=http://127.0.0.1:3000`. Для вебинара
используйте опубликованный адрес выше. Значение `BRIDGE_TOKEN` должно
совпадать в среде опубликованного сайта и `.env.local` ведущего.
`KOLER_ADMIN_CODE` открывает пульт изменения склада.

## Быстрая проверка перед эфиром

1. Откройте опубликованный адрес и общую Google-таблицу. Обновите лист и
   найдите последнюю контрольную заявку.
2. Войдите в пульт ведущего.
3. Установите для КР-001 собственный остаток 300 кг.
4. В блоке других поставщиков проверьте учебную строку «ПромКолор Опт»:
   доступно 2 000 кг, цена 361 ₽/кг, срок 4 дня, проверено 2026-07-31 09:00.
   Сверьте цену собственной части 349 ₽/кг и итог 718 400 ₽.
5. Запустите bridge. Убедитесь, что верхняя строка показывает подключённого
   агента, primary использует официальный API
   `deepseek/deepseek-v4-flash` с variant `max`, а отдельный reviewer —
   `deepseek/deepseek-v4-flash`/max.
6. Отправьте фото стены с человеком и текст «Покрасить стену как Красную
   комнату из Twin Peaks». Проверьте `ready/yellow/estimate`, диапазоны площади
   и килограммов, открытый URL референса, отсутствие RAL и вопросов.
7. На фото с человеком и окрашиваемой стеной отправьте «Покрасить это».
   Агент должен выбрать стену как разумный объект «Колера» и не спрашивать про
   волосы или человека.
8. Необязательный bonus-check: на synthetic фото с двумя одинаково
   правдоподобными неодушевлёнными объектами агент задаёт ровно один вопрос о
   цели без товара, цены и расчёта.
9. Отправьте свободное письмо на 2 000 кг КР-001. Проверьте дефицит 1 700 кг
   и маршрут руководителю без вопроса клиенту.
10. Проверьте подтверждённый учебный вариант «ПромКолор Опт»: 1 700 кг по
    361 ₽/кг, 4 дня, общая стоимость двух частей 718 400 ₽.
11. Убедитесь, что руководитель получил 2–3 варианта, а следующий контакт
    назначен поставщику или внутренней роли.
12. Запишите отправку диапазонной оценки без резерва. Для точного
    коммерческого предложения отдельно проверьте обязательный резерв.
13. Остановите OpenCode и убедитесь, что свободная заявка остаётся в очереди,
    spinner сменяется состоянием восстановления и доступна кнопка повтора.
    Записанный прогон покажите отдельной явной кнопкой готового примера.
14. Перед практикой верните КР-001 к учебному остатку 300 кг, а
    «ПромКолор Опт» — к 2 000 кг.
15. Верните bridge в online, отправьте ссылку участникам и предложите каждому
    пройти свободную заявку. Все карточки используют общий склад и попадают в
    дневной журнал.

После этой последовательности зритель видит причинную связь между письмом,
поиском выполнимой поставки, изменением живых фактов и итоговым ответом.

## GO / NO-GO

Статический GO возможен только при зелёных `lint`, `typecheck`, полном test
gate, build, `check-change-contract`, `check-eval-readiness`, contract audit,
local-only preflight и main-scenario check. Затем нужен отдельный live gate:
четыре webinar families по три последовательных Flash/max запуска с отдельным
Flash/max reviewer, всего 12
записей. Каждый запуск должен иметь отдельный hard pass, unique `callId`,
latency не более 700 секунд, шесть quality dimensions JTBD не ниже 90%,
attribution `raw-primary` → `guarded` → `reviewer` → `final` и отсутствие
recorded mixing. Synthetic live manifest с recorded vision не является MiMo run.

```bash
npm run lint
npm run typecheck
node --test tests/*.test.mjs
npm run build
node .agents/skills/manage-koler-changes/scripts/check-change-contract.mjs
node .agents/skills/evaluate-koler-agent-rules/scripts/check-eval-readiness.mjs
node .agents/skills/audit-koler-demo-contract/scripts/audit-contract.mjs --format=console
node .agents/skills/operate-koler-webinar/scripts/preflight.mjs
node .agents/skills/operate-koler-webinar/scripts/check-main-scenario.mjs
KOLER_LIVE_REPEAT=3 node tests/run-agent-wow-live.mjs \
  wow-02-washer-sports-car \
  wow-03-hostile-grill \
  wow-08-two-ton-shortage \
  wow-09-red-curtain-reference
```

Пока live gate не выполнен и не сохранён с зелёным manifest, статус — NO-GO,
даже если локальные проверки зелёные. Recorded demo не заменяет этот gate и
запускается только явным выбором поддержанного примера.
