# Колер

Интерактивный демо-стенд агентного отдела продаж завода красок.

Полное устройство стенда, границы текущей реализации и параллельный рассказ
для ведущего описаны в
[архитектуре стенда и сценарии вебинара](docs/ARCHITECTURE-AND-WEBINAR.md).

Посетитель пишет письмо-заказ, после чего система:

1. извлекает компанию, товар, объём, срок и коммерческие условия;
2. сверяет артикул, остаток, базовую и минимальную цену;
3. добавляет демонстрационный рынок и деловой контекст;
4. в живом режиме передаёт черновик ИИ-рецензенту, в автономном применяет
   проверку правил кодом;
5. применяет жёсткие правила зелёной, жёлтой или красной зоны;
6. готовит письмо, уточнение либо от двух до трёх вариантов руководителю;
7. сохраняет согласование и демо-отправку в журнале.

## Режимы

- **Автономный демо-режим** всегда работает на опубликованном сайте и
  демонстрирует три ветки на данных о красках и запасах, сгенерированных для
  вебинара.
- **OpenCode live** включается локальным мостом. Запросы с сайта обрабатываются
  моделями из подписки OpenCode Go на компьютере ведущего. Исполнитель может
  открыть публичные источники, а GPT-5.6 Sol проверяет его решение перед
  передачей результата на сайт.

В селекторе доступны:

- `DeepSeek V4 Flash` — быстрый исполнитель по умолчанию;
- `DeepSeek V4 Pro` — более подробная проверка;
- `GPT-5.6 Sol` — сильный проход; в этом режиме ИИ-проверку выполняет
  `DeepSeek V4 Pro`.

Журнал хранит выбранные модели, открытые источники, проверки, решение
руководителя и демо-отправку. Ведущий запускает отдельный ручной проход сильной
модели по этим записям и получает предложения для следующей редакции
инструкций.

## Локальный запуск

```bash
npm install
npm run dev
npm run bridge
```

Локальные параметры моста задаются в `.env.local`:

```text
STAND_URL=http://127.0.0.1:3000
BRIDGE_TOKEN=...
OPENCODE_PRIMARY_MODEL=opencode-go/deepseek-v4-flash
OPENCODE_REVIEWER_MODEL=opencode/gpt-5.6-sol
OPENCODE_ENABLE_EXA=1
```

`BRIDGE_TOKEN` защищает служебную очередь между сайтом и локальным OpenCode.
Одинаковое значение требуется локальному сайту и мосту.

## Полный цикл

- Зелёная зона: система готовит коммерческий ответ, пользователь завершает
  демо-отправку.
- Жёлтая зона: система формулирует точное уточнение, затем пользователь
  завершает демо-отправку. Ответ клиента станет новым входом после подключения
  корпоративной почты.
- Красная зона: участник выбирает в роли руководителя один из двух или трёх
  вариантов, согласует его, получает обновлённый черновик и завершает
  демо-отправку.

Заказы и события хранятся в D1. Опубликованный стенд ведёт общий счётчик работы
за день. Подключение настоящего почтового ящика добавляется отдельным входным и
выходным адаптером; карточка, правила, модели и журнал сохраняют тот же формат.
Стенд записывает статус `sent` в D1, почтовый адаптер в демонстрации отключён.

## Источники

Рабочая демонстрационная Google-таблица содержит вкладки:

- `Товары`
- `Правила`
- `Рынок`
- `Отрасли`
- `Заказы`

Опубликованный стенд читает подготовленный снимок этих данных из репозитория.
Ведущий открывает Google-таблицу по ссылке на первом экране и показывает
зрителям исходные остатки, цены, рынок и правила.
