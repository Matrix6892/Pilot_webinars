# «Колер»: передача Евгению Намоконову

Евгений, готова опубликованная версия «Колера» для вебинара об агентных
системах. Участник пишет заказ обычными словами, при желании добавляет
фотографию и видит весь путь: понимание задачи, вопросы, сведения о компании,
каталог, остатки, предложения поставщиков, решение, письмо и журнал действий.

- [Открыть «Колер»](https://koler-agent-demo.odinmaniac.chatgpt.site/)
- [Открыть общий журнал в Google Таблицах](https://docs.google.com/spreadsheets/d/e/2PACX-1vR7jeOl2r8s8mHvuFEkhJgG9F9kRiUknVTDG_Qt7RwX3nzj8AtVJihpdhX1kxxXCULV3d5D1xhUNBmU/pubhtml)

## Что уже работает

- Форма принимает свободный русский текст и фотографию. Клиенту достаточно
  описать задачу: например, показать забор или назвать площадь пола.
- Агент извлекает известные факты, задаёт только нужные вопросы и продолжает
  переписку под тем же номером заказа.
- Агент сверяет каталог, текущий остаток «Колера» и предложения других
  поставщиков. При нехватке товара он приносит выполнимые варианты с объёмом,
  стоимостью и сроком.
- Для понятного следующего шага работают три маршрута: «Готов ответить»,
  «Нужны детали» и «Решает руководитель». Руководитель получает подготовленные
  варианты и выбирает один.
- Панель администратора меняет остаток своей краски и доступный объём у
  поставщика. Открытый заказ пересчитывается, письмо обновляется, прежняя
  версия остаётся в истории.
- Кнопки подготовки резерва и записи отправки проводят заказ до конца
  показанного пути. Все действия входят в результат дня.
- Общий журнал связывает исходное письмо, ответы клиента, действия агента,
  решения руководителя, версии писем и изменения склада.

## Как пройти главный живой сценарий

1. Убедись, что на странице показана связь с OpenCode.
2. Выбери пример ГК «ПРОТЕК» с темой «Помогите выбрать краску для пола» и
   отправь заявку. Клиент указал площадь 800 м², но не назвал марку и массу.
3. Открой страницу заказа. Агент изучит сведения о компании, предположит
   назначение помещения и подготовит один понятный вопрос. Нажми «Записать
   отправку вопросов».
4. Выбери ответ «Медицинский склад» и нажми «Передать ответ агенту».
5. Агент рассчитает потребность 620 кг. При остатке «Колера» 420 кг он найдёт
   недостающие 200 кг у «Индустрии Покрытий», где доступно 260 кг, и принесёт
   руководителю готовый вариант совместной поставки.
6. Выбери вариант и нажми «Подтвердить выбранный вариант».
7. В панели администратора увеличь остаток краски для бетонного пола до
   700 кг. Агент заново прочитает склад, соберёт весь заказ из запаса
   «Колера» и подготовит новое письмо. Сравни версии до и после обновления.
8. Подготовь резерв товара, запиши отправку ответа и найди заказ по номеру в
   общем журнале и Google Таблицах.
9. После проверки верни остаток «Колера» к 420 кг, а доступный объём
   «Индустрии Покрытий» — к 260 кг. Так главный сценарий снова начнётся с
   поиска полного решения при нехватке своего запаса.

Код администратора хранится отдельно от этого описания.

## Как устроена рабочая цепочка

```text
Веб-форма → API заказа → D1 и R2 → защищённая очередь → OpenCode
          → MiMo V2.5 при наличии фото
          → DeepSeek V4 Flash
          → DeepSeek V4 Pro
          → программная сверка фактов
          → D1 → страница заказа и CSV → Google Таблицы
```

OpenCode работает на компьютере администратора. Он забирает заказы из
защищённой очереди, по очереди запускает модели, передаёт им подробные
инструкции, разрешённые источники и доступ к нужным инструментам, записывает
видимые шаги и возвращает результат в тот же заказ. OpenCode распределяет
работу между моделями и следит за порядком.

Сайт сохраняет историю заказа. При каждом запуске модель заново получает
переписку, свежие остатки склада и прошлые версии решения.

Роли моделей разделены:

- **MiMo V2.5** описывает только то, что видно на фотографии. Материал, размеры
  и условия использования подтверждает клиент.
- **DeepSeek V4 Flash** ведёт повседневную обработку заказа: разбирает заявку,
  берёт данные из разрешённых источников, готовит вопросы, расчёт, варианты и
  ответ клиенту.
- **DeepSeek V4 Pro** отдельным запуском проверяет готовое решение: факты,
  числа, источники, обещания клиенту и полномочия агента.
- **GPT-5.6 Sol** один раз подготовила подробные инструкции и критерии
  проверки. Повседневную работу по этим правилам выполняют Flash и Pro.
  Sol запускают вручную только для новой редакции инструкции.

После моделей программа ещё раз сопоставляет товар с каталогом, цену с
правилами, объём со свежим остатком и полномочия с выбранным маршрутом. Перед
решением руководителя, подготовкой резерва и записью отправки сервер повторяет
проверку изменяемых данных. Готовый ответ сохраняется в журнале заказа.

## Стек и хранилища

| Часть | Роль |
|---|---|
| React 19, Next 16, TypeScript | Интерфейс, страницы заказов и серверные API |
| Vinext и Vite | Сборка приложения для среды Cloudflare |
| Cloudflare Worker | Выполнение сайта и API |
| OpenCode | Локальный исполнитель: очередь, запуск языковых моделей, доступ к разрешённым инструментам и возврат результата |
| Cloudflare D1 | Основная SQL-база состояния |
| Drizzle ORM | Схема таблиц и типизированные SQL-запросы к D1 |
| Cloudflare R2 | Фотографии, приложенные к заказам |
| Google Таблицы | Просмотр общего дневного журнала |

D1 использует SQL, совместимый с SQLite. База хранит заказы и переписку,
события агента, историю версий решения, текущие остатки, историю изменений
склада, решения руководителя и состояние предложений поставщиков. Drizzle
описывает таблицы, индексы, ограничения и запросы в TypeScript.

Маршрут дневного журнала собирает строки из D1 и отдаёт CSV. Google Таблица
читает этот адрес формулой `IMPORTDATA`, поэтому на одном листе видны заявки,
вопросы, ответы, решения, письма, изменения склада, резерв и отправка. D1
остаётся источником текущего состояния; Google Таблица получает данные для
просмотра. Защищённый API для будущей записи остатков из таблицы уже
подготовлен, скрипт обратной записи сейчас не подключён.

## Текущие границы интеграций

- Входящий заказ сейчас создаёт веб-форма. Подключение корпоративного
  почтового ящика добавит автоматическое создание заказа из письма и
  вложений.
- «Подготовить резерв товара» записывает подтверждённый шаг в D1. Связь с
  корпоративной учётной и складской системой пока не создаёт фактический
  резерв.
- «Записать отправку ответа» сохраняет письмо и время в журнале. Почтовый
  шлюз пока не доставляет его клиенту.
- Остатки «Колера» и поставщиков живут в D1 и меняются через панель
  администратора. Подключение корпоративного склада заменит ручное обновление
  синхронизацией.
- Открытый поиск запускается только для заказов, где сведения о компании
  помогают принять решение. Система сохраняет найденные ссылки рядом с
  выводом для проверки.

Посмотри главный сценарий целиком, затем пришли обратную связь по трём вещам:
ясность пути для нового зрителя, убедительность изменения ответа после
обновления склада и понятность роли каждой модели.
